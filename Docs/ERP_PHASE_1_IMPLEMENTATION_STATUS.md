## WP-1.5 implementation note

The supplier invoice number is now a mandatory payable control.

### Database

Migration:
`2026_09_04_100500_enforce_supplier_reference_uniqueness.php`

Behavior:

1. Preflights all historical `(supplier_id, supplier_reference)` keys before changing the schema.
2. Treats surrounding whitespace as formatting and normalizes it.
3. Converts legacy blank references to `LEGACY-{bill_number}`.
4. Marks generated legacy values with `supplier_reference_backfilled_at`.
5. Makes `supplier_reference` non-nullable.
6. Adds unique key `bills_supplier_reference_unique` on
   `(supplier_id, supplier_reference)`.
7. Aborts the migration and names conflicting bill numbers if dirty duplicate data exists.

References remain reserved even when a bill is cancelled or soft-deleted. This matches the
database key and prevents reuse of historical supplier invoice evidence.

### Domain

`AccountingDocumentService::recordBill()` now:

- rejects null/blank supplier references with `SupplierReferenceRequired`;
- trims the reference before persistence;
- locks the supplier row before the duplicate check;
- checks all bills, including soft-deleted/cancelled history;
- translates unique-key races to `DuplicateSupplierReference`;
- writes a persisted refusal audit entry outside the failed bill transaction.

`approveBill()` rechecks the reference while holding the supplier and bill locks.

`Bill` also enforces the required/duplicate rule for Eloquent writes that do not use the
service. The database unique key remains the final guarantee.

### Filament

Bills now:

- require a supplier invoice reference;
- validate uniqueness scoped to the selected supplier;
- keep soft-deleted/cancelled references reserved;
- display whether a reference was supplier-provided or generated by the legacy backfill.

Purchasing Reports now include **Duplicate supplier invoice attempts**, sourced from the refusal
audit entries.
