# Demo Scenario Coverage

## Purpose

The deterministic demo month under `database/seeders/Demo/` is the realistic scenario dataset for the current IERP business flows. It is separate from `DatabaseSeeder` on purpose: it is local/demo-only, guarded against production, and drives real domain services so accounting, inventory, notifications, audit logs, and status transitions are generated by application behavior rather than direct fixture inserts.

Canonical flow source: `Docs/product/BUSINESS_FLOWS.md`.

## Run

```bash
php artisan migrate:fresh
php artisan db:seed --class="Database\Seeders\Demo\DemoMonthSeeder"
php artisan db:seed --class="Database\Seeders\Demo\DemoVerificationSeeder"
```

Do not run `migrate:fresh` against a database whose data must be preserved.

## Verification

`DemoVerificationSeeder` reports:

- record counts;
- accounting and inventory integrity checks;
- a dedicated **Canonical flow evidence** table for F-01 through F-21;
- dashboard metrics;
- status coverage, including Sales procurement requirements and CRM customer-return requests.

The canonical-flow table distinguishes real coverage from intentional non-applicability. F-20 must remain `N/A` until an actual van-warehouse/field-sale workflow exists in the product.

## Notes

- `DatabaseSeeder` remains focused on normal application defaults/legacy development data. The full deterministic month is intentionally invoked explicitly.
- Demo stages use the real services wherever the scenario represents a business transition.
- Dashboard target bands are presentation-density heuristics sized for this comprehensive deterministic month; accounting, inventory, lifecycle and canonical-flow checks remain the correctness gates.
