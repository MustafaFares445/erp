# Permissions & Help

IERP hides or blocks work the signed-in user is not allowed to perform.

## Why a page may not appear

A module or sidebar item can be hidden when your role has no accessible landing screen in that area.

This prevents navigation from advertising a module that the user cannot use.

## Why an action may not appear

Check these causes in order:

1. **Permission** — your role cannot perform the action.
2. **Status** — the record is not in a state where the action is valid.
3. **Prerequisite** — approval, source document, tracking information or configuration is missing.
4. **Ownership boundary** — the next action belongs to another module.
5. **Immutable history** — the transaction is posted/confirmed and requires correction instead of edit.
6. **Open child work** — an unfinished receipt, allocation, loan, repair, appointment or other child record blocks closure.

## Permission-sensitive examples

High-impact permissions commonly apply to:

- approvals;
- inventory posting;
- payment posting;
- accounting actions;
- warranty-date overrides;
- user/access administration;
- destructive/cancellation actions.

## Getting help

When reporting a problem, provide:

- module and page;
- record number/identifier;
- current status;
- action you expected;
- exact validation message;
- screenshot showing the issue, without private information;
- whether the issue is role-specific.

## User Guide link

Choose **User Guide** from the user menu to open the guide in a separate tab. The page-header **User Guide** button opens the article for your current screen. Switch the dashboard to Arabic to open the Arabic article.
