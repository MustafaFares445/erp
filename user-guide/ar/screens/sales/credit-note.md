# الإشعارات الدائنة

<IerpNavigationPath :items='["المبيعات", "الفوترة والمدفوعات", "الإشعارات الدائنة"]' />

<IerpPageSummary purpose="أنشئ إشعارات دائنة مضبوطة على قيمة مفوترة مع حفظ السبب والفاتورة المصدر وأي مصدر مرتجع." useWhen="عندما تحتاج للعمل على سجلات الإشعارات الدائنة أو متابعة دورة حياتها." owner="المبيعات" />

## نظرة عامة

أنشئ إشعارات دائنة مضبوطة على قيمة مفوترة مع حفظ السبب والفاتورة المصدر وأي مصدر مرتجع.

تدير المبيعات الدورة التجارية للعميل من عرض السعر والطلب المؤكد حتى التنفيذ والفوترة والتحصيل والتصحيح بالائتمان.

## طريقة الوصول

استخدم مبدّل الوحدات واتبع المسار **المبيعات ← الفوترة والمدفوعات ← الإشعارات الدائنة**. تختلف الخيارات الظاهرة حسب صلاحيات المستخدم.

## الشاشات ضمن هذا القسم

| الشاشة | استخدامها |
| --- | --- |
| صفحة القائمة | القائمة الرئيسية لـ الإشعارات الدائنة. استخدمها للبحث والفلترة والترتيب وفتح السجلات وتنفيذ الإجراءات المتاحة حسب صلاحيتك. |
| صفحة الإنشاء | نموذج إنشاء الإشعارات الدائنة. أكمل المعلومات المطلوبة وراجع الحقول التابعة قبل الحفظ أو الإرسال. |
| تفاصيل السجل | شاشة تفاصيل الإشعارات الدائنة. تجمع معلومات السجل والحالة والأعمال المرتبطة والسجل التاريخي والإجراءات المتاحة حسب السياق. |
| صفحة التعديل | شاشة تعديل الإشعارات الدائنة. تعتمد الحقول القابلة للتعديل على حالة السجل والصلاحيات وما إذا كانت العملية تجاوزت حد الموافقة أو الترحيل. |

## متى تستخدم هذه الصفحة؟

استخدم **الإشعارات الدائنة** عندما يكون العمل تابعًا لمسؤولية المبيعات. تحافظ الصفحة على السجل في الوحدة المالكة للحقيقة التجارية بدل تكراره في وحدة أخرى.

## المهام الشائعة

- ابحث عن السجل باستخدام البحث وطرق العرض والفلاتر ثم افتحه من قائمة العمل.
- أنشئ سجلًا جديدًا من إجراء الصفحة وأكمل أقسام العمل المطلوبة قبل الحفظ.
- راجع الحالة الحالية ومصادر السجل والإجماليات أو الأدلة والعمل المرتبط من شاشة التفاصيل.
- عدّل الحقول فقط عندما تسمح دورة الحياة وصلاحيتك بالتعديل المباشر.
- انقل السجل ضمن المسار باستخدام إجراءات مثل **تأكيد**، **Reverse**، **إنشاء PDF** بدل تغيير الحالة يدويًا.

## السلوك التشغيلي المتحقق منه

- Credit Note يصحح أو يخفض قيمة مفوترة للعميل، ولا يمثل بحد ذاته عملية إرجاع البضاعة المادية.
- حدد الفاتورة المصدر وتصنيف السبب وسجل سببًا واضحًا. الإجماليات مشتقة من بنود/سياق الإشعار وليست قيمًا حرة للتعديل.
- Stock Consequence يوضح علاقته بالبضاعة. عند اختيار Goods Returned يصبح Inventory Return مرحّل لنفس العميل مطلوبًا.
- Confirm هو مسار اعتماد الأثر المالي. Reverse عكس صريح؛ لا تحذف أو تعيد كتابة إشعار دائن مؤكد لإلغاء التاريخ.
- Generate PDF متاح بعد تأكيد الإشعار.

القائمة الرئيسية لـ الإشعارات الدائنة. استخدمها للبحث والفلترة والترتيب وفتح السجلات وتنفيذ الإجراءات المتاحة حسب صلاحيتك.

### طرق عرض الإشعارات الدائنة

استخدم **Draft** و**Confirmed this month** و**Confirmed** و**Sales returns** و**Reversed / Cancelled** لفصل التحضير عن الائتمانات المرحلة والائتمانات المرتبطة بالمرتجعات والعكس التاريخي. تبقي القائمة الفاتورة المصدر وأثر المخزون ظاهرين حتى يمكن تتبع التصحيح المالي إلى مصدر الفوترة وأي سياق مرتجع مادي.

يقوم **Export CSV** بتنزيل الصفوف الحالية بعد البحث والفلاتر. تبقى إجراءات التأكيد وتوليد PDF والعكس على شاشة السجل لأنها تغير أو توثق دورة حياة الإشعار.

هذه الشاشة قائمة عمل: استخدم البحث والفلاتر وطرق العرض لتحديد السجلات المطلوبة، ثم افتح السجل أو نفذ الإجراء المتاح حسب حالته.

<IerpScreenshot id="sales-credit-note-create" title="الإشعارات الدائنة — صفحة الإنشاء" description="نموذج إنشاء الإشعارات الدائنة. أكمل المعلومات المطلوبة وراجع الحقول التابعة قبل الحفظ أو الإرسال." path="المبيعات ← الفوترة والمدفوعات ← الإشعارات الدائنة ← صفحة الإنشاء" imageSrc="/images/ar/sales/sales-credit-note-create.png" />

نموذج إنشاء الإشعارات الدائنة. أكمل المعلومات المطلوبة وراجع الحقول التابعة قبل الحفظ أو الإرسال.

### اختر أثر المخزون صراحة

حدد العميل والفاتورة المصدر وتصنيف السبب، ثم اختر أحد آثار المخزون:

- **Goods returned** — يصبح مرتجع مخزون مرحل لنفس العميل إلزاميًا.
- **Customer retained goods** — التصحيح المالي لا يدعي رجوع البضاعة للمخزون.
- **No inventory movement** — عندما لا يملك التصحيح أثرًا ماديًا.

الإجمالي قبل الضريبة والضريبة والإجمالي النهائي المعروضة هنا سياق محسوب/للقراءة وليست قيم تصحيح حرة. تحدد البنود وقواعد الخدمة قيمة الائتمان المضبوطة.

### قبل إنشاء السجل

- تأكد من أن السجلات الرئيسية المشار إليها في النموذج فعالة وصحيحة.
- راجع المستند المصدر أو الخطوة السابقة إذا كان هذا السجل ناتجًا عن عملية أخرى.
- تأكد من امتلاك صلاحية إجراءات الإرسال أو الموافقة أو الترحيل التي ستحتاجها لاحقًا.

## الإجراءات والتحكم بدورة الحياة

يتضمن التنفيذ الحالي تعريفات لإجراءات مثل:
- **تأكيد** — يؤكد الالتزام التجاري الذي يمثله السجل وقد يفتح الأعمال التابعة.
- **Reverse** — ينفذ عكسًا صريحًا بحيث يبقى التاريخ المرحّل قابلًا للتدقيق.
- **إنشاء PDF** — يضع توليد أو إعادة توليد المستند القابل للطباعة في الطابور، ولا يعني الإجراء بحد ذاته فتح معاينة أو تنزيل فوري في المتصفح.

قد تغير الإجراءات الحساسة المخزون أو المال أو الموافقات أو حالة العملية. اقرأ نافذة التأكيد قبل المتابعة.

## حالات السجل

مفردات الحالة الحالية لهذا السجل هي:

<IerpStatus tone="neutral">Draft</IerpStatus> <IerpStatus tone="neutral">Confirmed</IerpStatus> <IerpStatus tone="neutral">Reversed</IerpStatus> <IerpStatus tone="danger">Cancelled</IerpStatus>

استخدم الإجراءات التي تعرضها الشاشة للانتقال بين الحالات. وجود الحالة لا يعني أن كل مستخدم يملك صلاحية تنفيذ الانتقال.

## التبويبات والسجلات المرتبطة

قد يحتوي السجل على معلومات أو مناطق عمل مرتبطة مثل:

- Credit Note البنود

تعرض هذه التبويبات السياق المرتبط ولا تنشئ مسارًا موازيًا للوحدة المالكة للعملية.

## الأثر على العمل

قد تنشئ المبيعات أعمال تنفيذ وفوترة ودفع ومحاسبة لاحقة، لكن تغيير المخزون يتم فقط عبر إجراءات المخزون.

## أسباب شائعة لعدم توفر إجراء

- لا يملك المستخدم الصلاحية المطلوبة.
- حالة السجل الحالية لا تسمح بالإجراء.
- توجد موافقة أو مستند مصدر أو إعداد مطلوب غير مكتمل.
- السجل المرحّل أو المؤكد أصبح ثابتًا ويحتاج مسار تصحيح أو عكس.
- توجد أعمال غير مكتملة في وحدة مرتبطة مثل الاستلام أو الدفع أو الصيانة أو التنفيذ.
