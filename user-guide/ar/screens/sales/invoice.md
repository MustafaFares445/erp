# الفواتير

<IerpNavigationPath :items='["المبيعات", "الفوترة والمدفوعات", "الفواتير"]' />

<IerpPageSummary purpose="أنشئ فواتير العملاء وأصدرها وراجعها مع فصل دورة حياة المستند عن الذمة والتسوية المالية." useWhen="عندما تحتاج للعمل على سجلات الفواتير أو متابعة دورة حياتها." owner="المبيعات" />

## نظرة عامة

أنشئ فواتير العملاء وأصدرها وراجعها مع فصل دورة حياة المستند عن الذمة والتسوية المالية.

تدير المبيعات الدورة التجارية للعميل من عرض السعر والطلب المؤكد حتى التنفيذ والفوترة والتحصيل والتصحيح بالائتمان.

## طريقة الوصول

استخدم مبدّل الوحدات واتبع المسار **المبيعات ← الفوترة والمدفوعات ← الفواتير**. تختلف الخيارات الظاهرة حسب صلاحيات المستخدم.

## الشاشات ضمن هذا القسم

| الشاشة | استخدامها |
| --- | --- |
| صفحة القائمة | القائمة الرئيسية لـ الفواتير. استخدمها للبحث والفلترة والترتيب وفتح السجلات وتنفيذ الإجراءات المتاحة حسب صلاحيتك. |
| صفحة الإنشاء | نموذج إنشاء الفواتير. أكمل المعلومات المطلوبة وراجع الحقول التابعة قبل الحفظ أو الإرسال. |
| تفاصيل السجل | شاشة تفاصيل الفواتير. تجمع معلومات السجل والحالة والأعمال المرتبطة والسجل التاريخي والإجراءات المتاحة حسب السياق. |
| صفحة التعديل | شاشة تعديل الفواتير. تعتمد الحقول القابلة للتعديل على حالة السجل والصلاحيات وما إذا كانت العملية تجاوزت حد الموافقة أو الترحيل. |

## متى تستخدم هذه الصفحة؟

- استخدم الفواتير لفوترة العميل بعد تنفيذ مؤهل أو لحالة فوترة مستقلة يدعمها النظام صراحة.
- حالة مستند الفاتورة منفصلة عن حالة التسوية المالية.

## المهام الشائعة

- ابحث عن السجل باستخدام البحث وطرق العرض والفلاتر ثم افتحه من قائمة العمل.
- أنشئ سجلًا جديدًا من إجراء الصفحة وأكمل أقسام العمل المطلوبة قبل الحفظ.
- راجع الحالة الحالية ومصادر السجل والإجماليات أو الأدلة والعمل المرتبط من شاشة التفاصيل.
- عدّل الحقول فقط عندما تسمح دورة الحياة وصلاحيتك بالتعديل المباشر.
- انقل السجل ضمن المسار باستخدام إجراءات مثل **الإصدار**، **Retry Deposit Application**، **إنشاء PDF**، **إرسال الفاتورة**، **تأكيد Receipt** بدل تغيير الحالة يدويًا.

## السلوك التشغيلي المتحقق منه

- استخدم الفاتورة Draft لمراجعة القيم قبل الترحيل. Issue هو حد الترحيل: يثبت المحتوى التجاري ويسجل Accounts Receivable وRevenue وDeferred Sales Tax.
- إرسال نسخة بريدية ليس حدثًا محاسبيًا، ويظهر فقط عند وجود PDF مخزن للفاتورة ولا يغير الدفتر.
- Generate PDF متاح للفواتير المصدرة ويولّد أو يعيد توليد المستند المخزن.
- Confirm Receipt يسجل طريقة تأكيد العميل للاستلام ويمكن أن يتضمن ملاحظات وتوقيعًا اختياريًا، ويظهر بعد حالة Sent.
- Record Payment يفتح إنشاء دفعة فقط لفاتورة مصدرة لها رصيد متبقٍ.
- Write Off Receivable يستخدم عندما تتوقف الشركة عن تحصيل ذمة صحيحة؛ Create Credit Note يستخدم عندما يجب تصحيح أو تخفيض قيمة الفاتورة نفسها.
- إذا فشل تطبيق عربون العميل تلقائيًا أثناء الإصدار، يعيد Retry Deposit Application فحص العربون المرحّل غير المخصص بطريقة idempotent.

القائمة الرئيسية لـ الفواتير. استخدمها للبحث والفلترة والترتيب وفتح السجلات وتنفيذ الإجراءات المتاحة حسب صلاحيتك.

### حالة المستند مقابل الحالة المالية

لا تعتبر **Document status** و**Financial status** شيئًا واحدًا. الأولى تصف دورة حياة الفاتورة، والثانية مشتقة من الدفع والائتمان والشطب. يعرض **Outstanding** القيمة التي بقيت مفتوحة بعد هذه الآثار.

يعمل عمود **Next action** وعروض Needs attention وOverdue وUnpaid وPartially paid كطوابير متابعة للتحصيل. ينزل Export CSV نتيجة الفواتير الحالية بعد البحث والفلاتر.

هذه الشاشة قائمة عمل: استخدم البحث والفلاتر وطرق العرض لتحديد السجلات المطلوبة، ثم افتح السجل أو نفذ الإجراء المتاح حسب حالته.

- **Financial الحالة**
- **الإجمالي المبلغ**

### الإصدار والتحصيل والتصحيح

الإصدار هو حد الترحيل المحاسبي: يثبت المحتوى التجاري ويرحل الذمم المدينة والإيراد وضريبة المبيعات المؤجلة. بعده استخدم **Record payment** للتحصيل، و**Create credit note** لتخفيض القيمة المفوترة، أو **Write off receivable** عندما تتوقف الشركة عمدًا عن تحصيل دين صحيح.

توليد وإرسال المستند منفصلان: يقوم **Generate PDF** بجدولة الملف، ويظهر **Send email copy** بعد وجود PDF ولا يرحل محاسبيًا. ويمكن تأكيد الاستلام بدليل مخصص.

### قواعد التعديل

التعديل لا يستبدل انتقال الحالة. بعد الموافقة أو الترحيل أو الإرسال قد يمنع النظام التعديل ويطلب مسار تصحيح أو عكس مخصص.

## ماذا يحدث بعد هذه الخطوة؟

- إصدار الفاتورة يرحّل أثرها المعتمد عبر المحاسبة.
- تقوم المدفوعات والتخصيصات بتحديث التسوية بشكل مستقل عن دورة حياة مستند الفاتورة.
- التصحيح يتم بإشعار دائن أو استرداد أو مسار مالي صريح بدل إعادة كتابة التاريخ.

## الإجراءات والتحكم بدورة الحياة

يتضمن التنفيذ الحالي تعريفات لإجراءات مثل:
- **الإصدار** — ينفذ الإجراء المسمى بعد التحقق من حالة السجل والصلاحيات والمتطلبات السابقة.
- **Retry Deposit Application** — يعيد محاولة الانتقال السابق باستخدام بيانات المصدر الحالية بعد التحقق.
- **إنشاء PDF** — يضع توليد أو إعادة توليد المستند القابل للطباعة في الطابور، ولا يعني الإجراء بحد ذاته فتح معاينة أو تنزيل فوري في المتصفح.
- **إرسال الفاتورة** — ينفذ الإجراء المسمى بعد التحقق من حالة السجل والصلاحيات والمتطلبات السابقة.
- **تأكيد Receipt** — ينفذ الإجراء المسمى بعد التحقق من حالة السجل والصلاحيات والمتطلبات السابقة.
- **تسجيل الدفع** — يتابع مسار الدفع المضبوط ويسجل الأثر المالي فقط بعد اكتمال المتطلبات.
- **Write Off** — ينفذ الإجراء المسمى بعد التحقق من حالة السجل والصلاحيات والمتطلبات السابقة.
- **إنشاء Credit Note** — ينشئ السجل المرتبط عبر المسار المعتمد مع الحفاظ على السجل الحالي كمصدر.

قد تغير الإجراءات الحساسة المخزون أو المال أو الموافقات أو حالة العملية. اقرأ نافذة التأكيد قبل المتابعة.

## حالات السجل

مفردات الحالة الحالية لهذا السجل هي:

<IerpStatus tone="neutral">Draft</IerpStatus> <IerpStatus tone="neutral">Issued</IerpStatus> <IerpStatus tone="primary">Sent</IerpStatus> <IerpStatus tone="danger">Written Off</IerpStatus> <IerpStatus tone="danger">Cancelled</IerpStatus>

استخدم الإجراءات التي تعرضها الشاشة للانتقال بين الحالات. وجود الحالة لا يعني أن كل مستخدم يملك صلاحية تنفيذ الانتقال.

## التبويبات والسجلات المرتبطة

قد يحتوي السجل على معلومات أو مناطق عمل مرتبطة مثل:

- Collaboration Entries

تعرض هذه التبويبات السياق المرتبط ولا تنشئ مسارًا موازيًا للوحدة المالكة للعملية.

## الأثر على العمل

قد تنشئ المبيعات أعمال تنفيذ وفوترة ودفع ومحاسبة لاحقة، لكن تغيير المخزون يتم فقط عبر إجراءات المخزون.

## أسباب شائعة لعدم توفر إجراء

- لا يملك المستخدم الصلاحية المطلوبة.
- حالة السجل الحالية لا تسمح بالإجراء.
- توجد موافقة أو مستند مصدر أو إعداد مطلوب غير مكتمل.
- السجل المرحّل أو المؤكد أصبح ثابتًا ويحتاج مسار تصحيح أو عكس.
- توجد أعمال غير مكتملة في وحدة مرتبطة مثل الاستلام أو الدفع أو الصيانة أو التنفيذ.
